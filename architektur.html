Wie MyLab gebaut ist

Ein Überblick für alle, die wissen wollen, wie MyLab gebaut ist. Anders als MySchool ist MyLab keine Mac-App, sondern eine Web-App auf einem Server: Die Sammlung gehört allen drei Fachschaften und muss von jedem Gerät aus gleich aussehen.

Grundsätze

  • Ein Code für Desktop und Handy. Eine Web-App, als App auf dem Home-Bildschirm installierbar. Mobile zuerst fürs Suchen, Fotografieren und Reservieren, Desktop für die längere Erfassung.
  • Einfach betreibbar. Ein Server, eine Datenbankdatei, ein Ordner mit Dateien. Sichern heisst kopieren, umziehen heisst kopieren und starten.
  • Kein Build-Schritt, kein Framework. Der Code im Repository ist der Code, der im Browser läuft.
  • Der Server rechnet. Filtern, Zählen und Konfliktprüfung passieren auf dem Server, nie im Browser über eine gekürzte Kopie. So bleibt MyLab auch mit 10 000 Elementen schnell.

Jede Änderung am Schema ist eine nummerierte Migration, die beim Start läuft. Bestehende Migrationen werden nie geändert.

Suchen und filtern

Die Volltextsuche nutzt den FTS5-Index von SQLite über Titel, Beschreibung und Tags; er wird nach jeder Änderung eines Elements neu geschrieben. Die Filter links liefern ihre Zähler aus derselben Abfrage. Die Liste lädt 200 Zeilen und blättert dann seitenweise nach. Mit einer Testdatenbank aus 10 000 Elementen dauert eine gefilterte Liste samt Zählern 33 ms.

Ein ungültiger Filter in einem Link entfernt den Filter nie, sondern zeigt nichts: Ein kaputter Link soll nicht plötzlich die ganze Sammlung zeigen.

Reservieren

Zeiten sind lokale Schulzeit ohne Zeitzonen-Umrechnung, das Lektionsraster (elf Lektionen à 45 Minuten) steht fest in der App. Eine einzige Funktion auf dem Server prüft Konflikte: Sie zählt, wie viele Stück zu jedem Zeitpunkt gleichzeitig unterwegs sind, und vergleicht mit der Anzahl des Elements. Bei Konflikt sucht sie die nächsten freien Zeiträume derselben Länge und überspringt Wochenenden.

Auf- und Abbauzeit sind bewusst ein Richtwert im Dialog und keine Sperre. Ob das Zimmer vorher frei ist, kann MyLab erst mit dem Intranet-Sync wissen.

Dateien

  • Hochgeladene Bilder verkleinert der Server mit sharp und erzeugt Vorschaubilder; Videos bekommen mit ffmpeg ein Vorschaubild, falls vorhanden.
  • Ein Speicher-Adapter legt die Dateien auf die Server-Platte oder in einen S3-kompatiblen Objektspeicher, ohne dass sich sonst etwas ändert.
  • Videos werden in Stücken ausgeliefert, damit sie auch auf dem iPhone spielen; unveränderte Dateien lädt der Browser nicht neu.
  • Grössenlimits: Bilder 25 MB, Dokumente 50 MB, Videos 500 MB; längere Videos als Link.

Betrieb

  • Zwei Container: die App und Caddy, das das HTTPS-Zertifikat selbst holt und erneuert.
  • Alle Einstellungen über Umgebungsvariablen: Adresse, Anmeldung, Speicher, Mail. Die Login-Art erkennt die App beim Start.
  • Ein Skript sichert Datenbank und Dateien, ein zweites spielt sie zurück; ein drittes bringt neue Versionen auf den Server.

Werkzeuge

  • Node.js mit dem eingebauten SQLite-Modul, Express für die Routen
  • SQLite mit FTS5 für die Volltextsuche
  • openid-client für die Anmeldung mit Microsoft
  • sharp und ffmpeg für Bilder und Videos
  • Oberfläche in Vanilla JS und CSS mit den Farb-Tokens des My-Designsystems, hell und dunkel
  • Automatische Tests für Schnittstelle und Browser: Der Testlauf startet einen eigenen Server mit leerer Datenbank und steuert Chrome ohne Zusatzbibliothek
